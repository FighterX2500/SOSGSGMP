## 13. The battle's Restart asks first

**Found.** The battle's own Restart (vanilla's rotate button, `BattlePanel`) opens vanilla's prompt: "restart" and a tick only. In a session SOSDET turns the restart into a vote (item 3), but the prompt doesn't say so.

**Fix.** In a session the prompt reads "Ask the players to restart the battle? Majority decides." with Ok and Cancel (vanilla's `IPromtYesNO` shows both buttons when it gets a Cancel action). Ok calls the vote as now. Outside a session it stays vanilla's. The multiplayer panel's Restart battle stays as it is.

**Where.** SOSDET patch `95-player-orders`, which already owns `view/battle/BattlePanel.java`: the click asks `Hooks.restartPrompt()` for the text and the Cancel action.

## 14. "Price" isn't centred over Buy and Sell

**Fix.** `MpPlayerWindow`'s Goods tab header centres Price over the two subcolumns, from their real widths, at every window size.

## 15. Sell shows 0 for goods this player doesn't export

**Found.** As Juchishi, the Goods tab of Gem Smashing Facility showed Sell 0 for goods Juchishi doesn't export. `MpPlayers.depotReceived` blanks Sell only while the other player's Import depot doesn't take the goods. A goods that this player doesn't export has an export price of 0, so Sell came out as 0 less the tariff, which is 0.

**Fix.** Sell is blank, with a hover saying why, while this player doesn't export the goods (their export price is 0). Buy is unchanged. A unit test covers the rule.

## 16. Player cities look different on each PC's world map

**Found.** The world map draws a capital from three numbers (`CSprite`): the population's size, the wall level and the garrison. For the wall level, vanilla counts the fortification tiles of the city loaded on this PC (`RDBuildings.levelWall`) when the capital is the local player's. For any other capital it uses the world's value, which for a player's capital is near 0. So each player sees their own city walled and the others' without walls. The population and garrison come from the world, the same on every PC.

**Fix.** Every player capital is drawn from the same numbers on every PC. The city's report carries its wall level: its fortification tiles over the map's width, as vanilla computes it, rounded to 1/100. On every PC, `levelWall` reads that reported value for any human's capital, the local player's own included. So a player sees their own city as everyone else sees it, updated with each report (a few seconds behind their own walls). Drawing only: the value never feeds the step or the hash.

**Where.** SOSDET: a new report field (the report format's version goes up; an old report without it reads 0), and a new hook in `world/region/building/RDBuildings.java` (`levelWall.pget`), which no patch owns yet.

## 17. "Station" instead of "Besiege" on a partner's capital

**Found.** With an army selected, the world map's move tool (`ToolMove`) shows Besiege over any capital vanilla lets the army besiege, a Colleague's or an Ally's included. A click orders the siege.

**Fix.** Over the capital of another player with an agreement that allows stationing (allies, colleagues, overlord and vassal), the hover says **Station** with the reason it can't yet if one applies (for example "march within 3 tiles first" isn't one: the click does that). A click marches the army to the tile vanilla would besiege from, at most 3 tiles from the centre. When it stands still there, this PC sends the Station command. A refusal on arrival (no room, the agreement ended) goes to the chat. Every other capital keeps vanilla's Besiege. The intent "station on arrival" is this PC's UI state only: it is dropped when the player gives the army any other order.

**Where.** A new hook in `view/world/ui/army/ToolMove.java` (the hover and the click), which no patch owns yet. The mod's stationing UI (`MpStationing`) holds the intent.
